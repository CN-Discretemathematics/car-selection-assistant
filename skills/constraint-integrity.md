# 约束完整性（用户声明的要求不能被链路丢掉）

来源：2026-09-14 用户实测对话（「必须是奔驰」被无视、追问后只列 3 款且答错能源）。
适用阶段：7（Agent）、9（迭代）。

## 两条铁律

**1. 用户明确声明的硬约束，必须在画像里有字段、在 SQL 里有过滤、在回复里有回执。**

事故链：`UserProfile` 有 budget/usage/passengers/body_type/energy_preference，**没有品牌** →
用户第一句「必须是奔驰」解析后无处存放 → 收齐预算/用途/人数后推荐了领克/小鹏/大众/林肯。
排查方法：拿用户原话逐句过一遍「这句话里的每个约束，落到哪个字段、哪条 SQL、回复里哪句话」——
三维缺一即为缺陷。`filters`（响应字段）是自查工具：把画像里的硬约束都暴露出来，
用户与开发者都能一眼看出哪条没生效。

**2. 盘点类问题必须读库，不能交给模型记忆。**

事故链：「奔驰都有哪些车型」落到通用对话分支 → 模型凭上下文答「我这边能确认的奔驰在售车型
有 3 款，都是纯电」。库里实际 **57 款、燃油（含油混）40 款**。凡是「有哪些/全系/有没有 X 的」
这类需要完整枚举的问题，都要有确定性路径（本项目：`brand_series_overview` → 读库给出
总数 + 能源构成 + 预算内清单 + 无价格数据的车系数），模型只负责措辞。

## 品牌解析的三个坑（都踩过）

1. **品牌名出现在车系名里**：「银河星愿怎么样」的「银河」是对车系的指代，不是「只要银河」。
   解析时必须传入已解析出的车系名做消歧，否则下一轮按「银河 + 燃油」过滤直接空结果。
2. **日常词歧义**：「理想的预算 20 万」里的「理想」不是品牌。对易混品牌名（理想/长安/大众/
   未来等）要求**强意图词**（买/购/只要/必须/想买…），而非「预算/要/看」这类过宽的词。
3. **只重申约束的消息**：「我强调过了，只要奔驰」不含购车意图词，若 `structured` 只看文本线索
   就会掉进通用对话分支（又变成模型记忆作答）。品牌线索必须计入「结构化输入」，回到确定性链路。

## 回归测试要点

- `tests/test_brand_constraint.py`：品牌解析（正向/否定/歧义/车系名消歧）、推荐结果**全部**属于
  该品牌、排除品牌后不再出现、盘点计数来自库内、`vehicle_search(brand=...)` 可按品牌名查、
  重申约束的消息必须回到确定性链路并给出该品牌内推荐。
- 验证要跑**真实对话**（`.tools/repro_brand_conversation.py` 打真实后端），不只看单测：
  单测覆盖函数，端到端才能暴露「分支走错」这类问题。
