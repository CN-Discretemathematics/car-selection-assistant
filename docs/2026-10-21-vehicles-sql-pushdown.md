# `/vehicles` 的过滤与分页下推 SQL（2026-10-21）

> 分支：`perf/vehicles-sql-pushdown`｜基线：`origin/main`（不依赖任何未合入分支）

## 背景

三件事撞在一起：

1. **工程标准 R7.2**（`docs/engineering-standards.md`）：**禁止**「全表载入后在 Python 里
   过滤分页」，必须下推 `LIMIT` / 聚合到 SQL。`/vehicles` 正是这个形态
   （台账 `refactoring-roadmap.md` 里那条「`vehicles/router.py:41-115` 全表载入后 Python
   过滤分页（无 SQL 下推）」一直挂着）。
2. **性能实测**（本地快照库 908 车系）：默认查询 **46 ms**——把 908 个在售车系全载进内存，
   还要为**全部**车系算一遍价格区间（≈9k 款型）与最新销量（当月销量全扫），
   最后只展示 20 条。
3. **产品口径已拍板**（2026-10-21）：关键词搜索覆盖「**品牌名 + 别名 + 车系名**」——
   核对发现这正是既有 `keyword_score` 的口径 ✓，所以**用户可见的行为不变**，
   本笔只改「怎么取数」。

## 机制

新模块 `app/vehicles/listing.py`：过滤 + 价格区间 + 最新销量 + 排序 + 分页**整体下推 SQL**。

- **关键词相关度排序仍由 `keyword_score` 独占**（Python 侧）——
  它是「搜得到与问得到一致」的口径唯一主人，**不在 SQL 里重写一遍**（重写就是漂移）。
  有关键词时 SQL 只负责把过滤后的候选集取出来，Python 侧再打分、排序、切片。
- **能源类型是 JSON 列**，过滤用**引号定界的 LIKE**（`%"BEV"%`）：两栈的 JSON 文本都是
  `["BEV", "PHEV"]` 这种形态，元素被引号包着，故不会误命中 `BEVX`。
- **总数用窗口函数**一次算完——另跑一条 `COUNT` 会把整条聚合**再算一遍**（实测直接翻倍）。
- **价格区间只为当页算**（默认路径）：它只用于展示时，不必为 908 个车系全量聚合。

## 实测

### 性能（本地快照库 908 车系，同一进程内连跑）

| 查询 | 改前 | 改后 |
| --- | --- | --- |
| 默认（销量倒序） | 46 ms | **31 ms** |
| 价格过滤 ≤20 万 | 42 ms | **9 ms** |
| 能源=新能源 | — | **8 ms** |
| 第 3 页 | — | **6 ms** |
| 关键词「比亚迪」 | 22 ms | 30 ms |

关键词路径略慢：候选集要整批取回给 Python 打分（那条路径的结果集本来就小，
且它才是「搜得到与问得到一致」的地方）。**换来的是**：默认路径不再为 908 个车系
物化 ORM 对象、不再为全部车系算价格区间。

剩下的 ~25 ms 是 `latest_sales_month` 的**全表扫描**（`monthly_sales.month` 无索引）——
`/home` 同样付这笔钱。要根治得加索引，那是**迁移**，而迁移必须接在分支 8 的迁移之后
（否则 alembic 两个 head）⇒ **已登记，不在本笔**。

### 口径等价（**旧实现当 oracle**）

`tests/test_vehicles_sql_pushdown.py` 里保留了改前的原逻辑作 oracle，
在种子数据 + 查询矩阵上逐条比对「每页的车系 id 序列」与「总数」；
另在**真实快照库**上跑了同一矩阵的 24 种查询形状（含关键词的真实命中：
「汉」3 条、「比亚迪」34 条、「理想」5 条）——**24/24 全部与旧实现一致**。

### 等价性回归当场抓出的真实漂移

开发中把「燃油」的 SQL 判据写成「**不含全部三种新能源**」，而旧口径是
「**存在某个非新能源类型**」（能源枚举共 5 值：新能源 = BEV/PHEV/EREV）。
两者不等价：纯电车（只含 BEV）会被前者算成燃油。
**等价性回归当场报出**（`energy_type=fuel` 旧 3 条 / 新 7 条）——这就是为什么要写 oracle。

## 守卫（2 条用例 + 变异 5/5）

| 约束 | 用例 |
| --- | --- |
| 与旧实现**逐条等价**（18 种查询形状 × 种子数据） | `test_sql_pushdown_matches_the_legacy_implementation` |
| 越界页码钳制到最后一页（评审 P2） | `test_page_is_clamped_to_the_last_page` |

变异脚本 `.tools/mutate_vsp.py`（本地专属，不入库）**5/5**：燃油判据写反 /
价格过滤方向反了 / 越界页码不钳制 / 能源过滤整个不生效 / 销量排序失效。

夹具里**刻意**放了两类刁钻数据：价格区间跨阈值的车系（15 万~25 万）——
否则「用最高价判」与「用最低价判」在单价车系上完全一样，M2 那种变异根本测不出来；
以及没有在售款型（价格区间为空）的车系。

## 行为变更

| 场景 | 变更 |
| --- | --- |
| 用户可见的列表内容 | **不变**（口径逐条一致，24/24 形状验证） |

## 已知边界

- **关键词路径仍在 Python 侧排序**：相关度口径不重写（见上）。
- 剩下的 ~25 ms 是 `latest_sales_month` 的全表扫描（`month` 列无索引）——
  根治要加索引，属迁移，受 alembic 顺序限制（须接在分支 8 的迁移之后）⇒ 已登记。
- 等价性验证覆盖的是**本地快照库**；生产库的别名/能源分布若与快照不同，
  仍需按同一矩阵再跑一次（脚本可复用）。
