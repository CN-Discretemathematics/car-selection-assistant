# 「主动说」三处机制与计划 §1.2 判据的关系（2026-10-21 实测）

> 分支：`feat/proactive-statement-rule`｜对应计划 §七「『主动说的三判据可泛化』」那条判断

## 一、计划怎么说的

- **§1.2 的判据**：「当前轮存在『**用户已知但本轮未复述**』的关键状态，
  且说出来能改变用户的选择」。
- **§1.3 列的三处现成机制**：`_priority_phrase`（回执用户刚说的话）、
  `_unlock_note`（解释范围为什么变了）、`next_clarification`（追问缺的那一项），
  并说「**三者的共同结构即上表『主动说的判据』**」。

## 二、实测：三处的**触发前提各不相同**

| 机制 | 代码里的实际触发前提 | 与 §1.2 判据 |
|---|---|---|
| `_priority_phrase` | 画像里**有可复述的东西**（含**记忆带回来的** ✓） | **正是它** ✓（当那东西来自跨会话记忆时 ✓） |
| `_unlock_note` | 锁定车系与**本轮新需求**冲突 ⇒ 解释范围为什么变了 | 不同：本轮**新出现**的状态 ✓ |
| `next_clarification` | 还**缺**一项 ⇒ 最小化追问 | 不同：缺的是**还没有**的东西 ✓ |

⇒ **更正**：§1.3 那句「三者的共同结构即『主动说的判据』」**不准确** ✗ ——
只有 `_priority_phrase` 落在那条判据上；另外两处各有各的前提 ✗。

## 三、判据真正的落点：**记忆回填后的回执**

实测（跨会话：上次说过预算，这次用户只说「平时上下班通勤」）：

```
clarification.question = '已记下：预算 20-25 万；用途通勤。平时几个人坐？'
```

⇒ 「上次说过的预算」这次**已知** ✓、而用户**本轮没复述** ✓ ⇒ 系统**说出来** ✓
（「已记下：预算 20-25 万」✓）⇒ 计划 §1.2 那条判据**在代码里生效** ✓
（`next_clarification` → `_priority_phrase` → `engine.py`）✓。

同一轮里**只问还缺的那一项**（人数 ✓）——记忆把预算补上了，就不再问预算 ✓。

## 四、那么三处**真正**共享的是什么

不是同一条触发判据，而是**同一种做法** ✓：

1. 都在**同一条回答**里多说一段 ✓；
2. 都**只说画像/库里已有的事实**（不猜不补 ✓）；
3. 都与**本轮的决策直接相关**（回执 / 解释 / 追问 ✓）。

⇒ 若要把它们抽象成一个 module，该抽象的是**「怎么说」**（三套措辞 ✓），
**不是「什么时候说」**（三套前提 ✓）——后者强行统一会把
「解释范围变了」说成「你以为我们记得」这类错话 ✓。

## 五、用例（把这个结论钉住）

`backend/tests/test_proactive_statement_rule.py`（5 个）：

- 记忆回填后，追问的回执里**必须**出现那个预算 ✓（= 判据在代码里生效 ✓），
  且只问**还缺**的那一项 ✓；
- `_profile_summary` 只复述**画像里已有**的 ✓；
- `_priority_phrase` 回执**画像里已有**的，**不猜不补** ✓；
- `next_clarification` **一次只问一项** ✓；
- `_unlock_note` 只在**范围变了**时出现 ✓。

pytest：全量通过 ✓；ruff：与基线一致 ✓。
