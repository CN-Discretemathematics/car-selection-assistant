# 排除语境显式化：把「排除」从字符串暗号变成参数（2026-10-21）

> 来源：2026-10-21 代码审查的 **Major M1**（结构问题，非当前缺陷）。
> 分支：`chore/structure-and-doc-truth`（与 M2、文档事实对齐同批）

## 一句话

跨会话记忆回填品牌排除项时，此前靠**拼一句「不要 X」**把语境暗示给解析器；
现在语境是**显式参数** ⇒ 语境不再寄��在「否定词表 + 4 字窗口」两个隐式约定里。

## 之前长什么样

```python
# agent/preferences.py::resolve_brand_names
hints = resolve_brand_mentions(db, f"不要{clean}")
```

调用方**已经知道**语境是「排除」（记忆里存的就是「用户明说不要的品牌」），
却要靠**拼一句话**把它告诉解析器。⇒ 语境落在两个隐式约定上：

1. `catalog/brands.py::NEGATION_PREFIXES` 这个否定词表；
2. 「品牌名前 4 字」这个窗口。

## 为什么这是结构问题（而不是「写法不好看」）

那套约定一旦被改——换个词表、把窗口从 4 改成 2——这条路径会**静默失效**：
没有报错、没有日志、测试也可能照过（只要测试里恰好带了个否定词），
只是「排除项又不见了」。

而排除项失效**直接毁掉答案**：用户说「不要大众」，系统照常推荐大众的车
（计划 §1.2：硬约束排除项错了直接毁掉答案）。

2026-10-21 那次「歧义品牌排除项静默失效」就是同一类问题的又一次现身——
只不过那次是**词表与守卫的顺序**问题，这次是**语境该由谁说**的问题。
两次都落在同一个地方：**一个本该显式的约定，被藏在了字符串与顺序里**。

## 改了什么

`catalog/brands.py::resolve_brand_mentions` 新增关键字参数 `exclude_context`：

| 调用 | 语境来源 | 歧义守卫（大众/理想/长安…） |
| --- | --- | --- |
| `resolve_brand_mentions(db, "预算15万，不要大众")` | **文本里的否定词**（不变） | 否定语境下不适用 |
| `resolve_brand_mentions(db, "大众", exclude_context=True)` | **调用方显式声明**（新） | 排除语境下不适用 |
| `resolve_brand_mentions(db, "大众的预算 20 万")` | 无（不变） | **仍然拦着** |

`agent/preferences.py::resolve_brand_names` 改用显式参数：

```python
hints = resolve_brand_mentions(db, clean, exclude_context=True)
```

⇒ **记忆回填这条路径不再依赖否定词表**。

## 验证

新增 `backend/tests/test_exclude_context_explicit.py`（4 条）：

| 断言 | 抓什么 |
| --- | --- |
| 显式参数按排除语境解析歧义品牌 | 新接口真的生效 |
| **词表清空后，记忆回填照样解析出排除项** | **结构真的修好了**（旧的拼字符串做法在这里会红） |
| 非排除语境的老行为逐字不变 | 没有顺手改坏别的东西 |
| 排除语境不产出正向约束 | 「不要大众」不会变成「只要大众」 |

**变异测试**：把 `resolve_brand_names` 退回 `f"不要{clean}"` ⇒
「词表清空后仍能解析」那条**变红** ⇒ 断言不是恒真的空转断言。

## 边界

- 本笔**不改**任何行为结论：记忆回填的解析结果与改前**逐字相同**
  （旧路径走的是否定语境，新路径走的是显式排除语境，两者语义一致）。
- 本笔**不删**否定词表：文本里的自然语言否定（「预算15万，不要大众」）
  仍然靠它识别——那才是它该干的活。
