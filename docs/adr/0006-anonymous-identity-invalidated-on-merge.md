# 匿名身份合并后失效，且合并不可撤回

**状态**：accepted（2026-10-21 用户拍板；已实现的语义照抄本 ADR，
未实现的部分——合并记录表与设置页展示——见
[待立项项落地方案](../2026-10-21-deferred-items-execution-plan.md) 第五节）

## 背景

`merge_anonymous_into_user`（`backend/app/agent/identity_merge.py:76`）在登录后把匿名身份的
偏好记忆与拒绝反馈搬进账户身份，并做两件事：

- 把匿名身份标成 `merged`（`identity_merge.py:142`）；
- `get_identity_by_token`（`backend/app/agent/preferences.py:118`）**只认 `status="active"`** ⇒
  旧匿名 token 立刻查不到身份。

这两条在代码里已经是既成事实，但**为什么**、以及「能不能反过来」，此前没有成文拍板。

## 考虑过的选项

1. **合并后匿名 token 继续有效**：**不采纳**。
   记忆表按 `(identity, category, key)` 唯一、反馈表按 `(identity, variant_id)` 唯一——
   两个身份各存一份 ⇒ 用户在 A 设备改的预算，B 设备看不到；
   被拒的款型在一处被排除、另一处不被排除 ⇒ **推荐结果随设备漂移**。
   这正是 `preferences.py` docstring 说的「数据会**分叉**到两个身份上」。
2. **合并后匿名 token 失效**（**采纳**）：客户端改用账户身份的 token。
3. **合并可撤回**（把数据搬回原匿名身份）：**不采纳**。
   撤销要先定义「搬到哪儿」——搬回原身份 = 恢复那枚已失效的 token = 重新打开分叉的口子。
   而且**撤回权已经存在**：`DELETE /me/data`（`auth/router.py:236`，**没有** `/auth` 段
—— 2026-10-21 实测纠正）删的是
   **个性化数据**（记忆 + 反馈），账号与收藏不动。
   「撤回数据」与「撤销合并」是两件事，不要混。

## 决定

1. **合并是一次性的、终态的**：不可撤回。
2. **合并后旧匿名 token 立即失效**；客户端**必须**改用合并响应返回的账户身份 token
   （`auth/router.py:211-216` 的 `MergeIdentityOut.token`）。
3. **明文只给一次**：账户身份**新建**时返回 token；账户身份已存在时返回空串
   （客户端手上应已有那枚——库里只有哈希，明文无法重取）。
4. 每次合并留**一行合并记录**（时间、匿名身份 id、账户身份 id、搬了几条记忆 / 几条反馈）——
   供设置页展示「已从匿名设备合并 N 条记忆」。

## 后果

1. 客户端**必须**实现「合并后换 token」，否则用户合并完**立刻失忆**：
   数据搬过去了，客户端却还在拿旧 token 读写匿名身份 ⇒ 读不到搬走的东西。
   这是本 ADR 唯一一条**必须改客户端**的约束。
2. 合并不可撤回 ⇒ 合并**必须由用户显式触发**，不能后台自动做。
3. ⚠️ **已知边界**：账户身份 token **无法重新签发**（库里只存哈希）。
   客户端把它弄丢，就等于丢了账户侧个性化数据的访问权——
   产品文案必须说清，必要时提供「重置账户身份」的出口。
4. 合并记录表是**新增表** ⇒ 迁移必须接在现有迁移之后（单头，不分叉）。
