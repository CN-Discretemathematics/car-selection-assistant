# 数据规模与汽车之家对齐，差异化在可溯源

**状态**：accepted（2026-10-20 用户拍板）

本项目的数据规模**与汽车之家对齐**：车系、款型、品牌三级全部来自汽车之家，**不因为「规模不够」而另接数据源**。
对外差异化不是「更全」也不是「更准」（数据同源，不可能更准），而是**可溯源**——
同一个数据源上，每句回答都能被追问到出处，答不了就明说。

## 理由

1. **规模本已同源，不构成差异维度**。库内 **1078 个在售车系 / 7888 款型 / 132 个品牌**，
   `external_series_refs` 覆盖 **1078/1078** 车系。汽车之家官方口径是 2000+ 车系、近 2 万款型、130+ 品牌——
   同一量级。「我们数据更多」不是能成立的主张，也不该是目标。
2. **真正的差异在口径，不在规模**。汽车之家的选车与对比是**黑盒**（ML 排序 + 内容运营 + 口碑筛选）；
   本项目的确定性内核是：硬约束下推 SQL → 七维确定性打分（评分 v2，见
   [ADR-0008](0008-scoring-v2-seven-dimensions.md)）→ 每句数字可溯源到库内事实 →
   不可回答时显式标注「官方资料未披露」。
   同样的数据，**一个能问出出处，一个不能**。
3. **目标价格带选得对**。20–30 万区间参数表看不出优劣、体验差很多，正是内容生态与口碑优势最薄弱、
   可溯源价值最高的区间。
4. **不接第二个数据源**。汽车之家的口碑 / 评测 / 论坛内容本项目不碰（撞「绝不编造动态驾驶感受、
   车主口碑、优惠信息」原则）。补足的是**结构化 + 官方叙述**——`official_page_url` 恒为 0/1078
   是**已知且如实标注**的缺口，不靠猜域名补。

## 考虑过的选项

- **接第二个数据源补规模**：不采纳。规模已对齐；接新源会引入「同一车系两个来源谁为准」的冲突，
  且 `external_series_refs` 的唯一键是 (source_id, external_id)——可以扩展，但**没有需要扩展的理由**。
- **以「AI 选车顾问」作为对外定位**：不采纳作为**差异化**主张。汽车之家已有 12 维度多轮问答收敛、
  「智能选车路径引导」与 AI 助手，撞车。顾问**形态**保留，差异化落在**可追问**上。

## 后果

1. **可溯源必须被度量**。目前评测量的是检索准不准（Hit@5 / pair-coverage）、答得对不对
   （faithful_db / 拒答诚实性），**没有量「用户能否问出这句话的出处」**。
   故新增 [可追问率](../../GLOSSARY.md#回答与可信度) 指标——它是唯一能把差异化变成可度量承诺的动作。
2. **规模对齐是持续维护，不是一次性达成**。SKU 抓取是逐车系的慢操作（1 秒/页），
   与销量榜天然不同步，缺口会自然产生（201 个在售车系有销量但 0 款型）。缺口必须**常驻可见**，
   而非抓完就算。
3. **「全部款型停售」不是缺口**。它是被上游标记的真实状态，详情页显示「暂无在售款型数据」本就正确。
   与「完全没有任何款型」的真缺口必须分开计数，否则回补指标永不收敛。
