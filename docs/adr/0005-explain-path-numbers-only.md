# 解释路径只守数字，不守名字

**状态**：accepted（2026-10-21 用户拍板；实施待立项，方案见
[待立项项落地方案](../2026-10-21-deferred-items-execution-plan.md) 第一节）

## 问题

仓库里有三条会产出用户可见文案的链路，守卫强度**不一致**：

| 链路 | 位置 | 数字守卫 | 名字守卫 |
| --- | --- | --- | --- |
| 对比路径 | `engine.py:1688` | ✓ | — |
| 工具循环 | `engine.py:2113` | ✓ | ✓ |
| **解释路径** | `engine.py:2587` `_explain` | **✗** | **✗** |

`_explain` 把 `result["variants"][:5]`、`evidence` 与 `llm_profile_view(profile)` 塞进模型上下文，
模型返回什么就返回什么，只过一道 `safety_guard`（安全词），**没有任何数字校验**。
而「每句数字都能追到出处」是本项目的差异化承诺（ADR-0003）——
承诺在解释路径上目前是**空的**。

## 考虑过的选项

1. **接上现成的 `validate_tool_answer`（数字 + 名字一起守）**：**不采纳**。
   名字守卫的容差匹配（`_name_covered`，`answer_contract.py:115`）在解释路径上**误杀面太大**：
   解释路径本来就要复述车系名、款型名、参数名，而这些东西**不全在**工具返回的名字池里
   （画像里的品牌标签、用户自己说过的车名都在池外）。一守名字，合法解释会被成片打回模板。
2. **什么都不做**：**不采纳**。解释路径是用户最常看到的「为什么推这台」入口，
   空承诺等于假承诺——这正是本仓反复记录的「未验证的效果断言」。
3. **只守数字，允许集与工具循环同口径**：**采纳**。

## 决定

- **允许集** = 候选款型 + 检索证据 + 画像（+ 用户消息里出现过的数字），与工具循环**同一套口径**：
  `tool_result_universe`（`answer_contract.py:176`）收工具返回，
  `numbers_in(message)` + 画像里的预算 / 人数（`engine.py:2018-2024`）收用户自己说过的数，
  判定用 `answer_numbers_allowed`（`answer_contract.py:98`）。
- **只守数字，不守名字**。
- 违规处理**照抄工具循环的三级**，不就地另写一套：
  违规 → 把违规项回灌让模型**重写一次** → 仍不合格 → **回退确定性模板**并打 `contract_fallback=True`
  （`engine.py:2113-2152`）。实现就**接在 `_explain` 内**，不新建第二个守卫 module。
- **不改**候选集、不改打分、不改排序（红线）。

## 后果

1. 解释路径会**第一次**出现「用户看到的回答被逐字替换」的场景：回退模板时用户看到的是模板文案，
   不是模型的解释。因此 `contract_fallback` 必须**可观测**（打标 + 计数），
   否则解释质量的下降在监控上不可见。
2. ⚠️ **量纲坑（实施时必须先解决）**：`answer_numbers_allowed` 比的是**数值 + 0.01 容差**（`_number_hit`），
   而画像里的预算存的是**元**（`200000`），文案里通常写「**20 万**」——
   文本里解析出来的是 `20`，与池里的 `200000` 差 4 个数量级 ⇒ **会被误判成编造**。
   工具循环之所以没踩到，是因为它的允许集**含用户原话里的数字**（用户自己写「20 万」就有 `20`）。
   解释路径的用户消息不总带数字 ⇒ **允许集必须同时补上万元量纲**（`budget.max / 10000` 等）。
   这条是实施的第一步，不是可选项。
3. 解释路径的输出**不可测**——本机没有 LLM key，但守卫本身**不需要**它：
   复用 `tests/test_answer_contract.py` 已有的 `_FakeLLM` 范式，
   四条路径各有断言（合法通过 / 数字违规重写 / 重写仍违规回退 / LLM 不可用回退）。
