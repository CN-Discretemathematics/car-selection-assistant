# 画像落账户存储

**状态**：proposed（2026-10-20 用户拍板，实施随 Phase 1 落地）

`UserProfile` 自创建起就声明「事实只来自用户对话，不落账户存储」（`backend/app/agent/schemas.py:15`）。
那是一条**刻意的产品决定**，不是疏漏：模型推断出来的偏好如果落库并参与筛选，猜错会静默砍掉整个候选集——
用户看不到原因，只看到「它推荐的车我根本不会买」。

2026-10-20 决定**推翻**这条声明：新增 `preference_memories` 表，把跨会话的偏好持久化。
产品方向是「跨会话、可持续个性化的对话式购车顾问」；单会话记忆无法支撑该定位——回访用户每次从零开始。

## 考虑过的选项

- **在 `users` 表加 `anonymous_id` 列**（评审稿建议）：**不采纳**。一个账户可以对应多个匿名设备（多浏览器 / 多设备），
  一行放不下；匿名身份登录后合并进账户，匿名身份需要**失效**，而不是继续有效；合并还需要偏好去重语义。
  仓库已有同构先例 `ExternalSeriesRef`（external_id → series_id + 唯一约束 + 独立映射表），故采用独立映射表
  `anonymous_identities`。
- **复用 `favorites` 表存偏好**：**不采纳**。favorites 是「收藏」，语义与生命周期都不同。

## 后果

1. **`schemas.py` 的 docstring 必须同步改**，否则代码与文档口径分裂——`doc_sync_check.py` 会抓。
2. **记忆中可能有陈旧错误**：用户换了工作、搬了城市，旧的预算 / 用途会持续影响推荐。
   缓解靠 `expires_at` + 可见可编辑可删除，但**缓解效果未经验证**，是本方向最不确定的一环。
3. **多轮下模型编造的诱惑变大**：单轮有「库里没有就说未披露」的 60/60 拒答诚实性兜底；
   多轮里模型带着历史上下文更容易编造而不是拒答。缓解是记忆只存封闭枚举 + 答案契约 + 端到端接缝。
4. **写入只针对确认过的偏好**：`confirmed=True`（用户明说或确认过）才落库，`inferred` 在 shadow 阶段只落日志。
5. **回填必须复用 `merge_profile`**：不新建第二个画像合并器——两套口径必然漂移，这是仓库反复记录过的教训。
   持久化记忆先翻译成 hints 形状再喂给它，翻译器单独成 module，正确性判据是往返测试
   （hints → memory → hints 逐值相等）。
6. **`FORBIDDEN_FIELDS` 仍然禁止出现在推断通道**：`body_type` / `energy_type` / `budget` 可因**用户明说**而持久化
   （`explicit`），但不得由模型推断产生（`inferred`）。
