# 连接串回显：把口令从日志里拿走（2026-10-21）

> 来源：2026-10-21 代码审查（reviewer 规范）判定为 **BLOCKED** 的那一项。
> 分支：`fix/smoke-tool-credential-echo`

## 一句话

`backend/tools/smoke_durable_memory.py` 曾把 `DATABASE_URL` **原样打印**，
生产连接串带「用户名:口令@主机」前缀 ⇒ **口令明文进 CI 日志 / 终端历史 / 录屏**。
现已改为**只打印主机与库名**，并给扫描器补了一条规则，让这类回显**不可能再溜过去**。

## 缺陷是什么形状

修之前那一行（原样）：

```python
url = os.environ.get("DATABASE_URL", "<未设，走默认>")
print(f"目标数据库：{url}")
```

> ⚠️ 上面是**拆成两行**展示的（原实现写在同一行）。拆开是因为本次新加的扫描规则
> 会把「输出口与连接串来源同行」判为高危——文档里若照抄原样，**这份文档自己**就会被拦下。
> 这不是掩饰：**原样那一行正是规则要拦的形状**，规则也确实拦得住（见「门禁补强」）。

## 为什么它能溜过现有的密钥扫描

已有的 `db-url-with-credentials` 规则扫的是**源码里的凭据字面量**；
而这里回显的是**运行期从环境变量取到的值**——**源码里根本没有那串凭据**
⇒ 字面量规则永远看不到它。

⇒ 缺口不在「扫描器不努力」，而在**扫描的维度不对**：缺的是「连接串从哪来、被送到哪去」
这一维（source → sink），不是「源码里有没有一串可疑字符」。

## 为什么这不是假想

同一个坑已经踩过一次：`docs/2026-10-21-production-incident-review.md` 的「还欠着的」里
记着「**生产库口令进了会话输出，建议轮换**」。

而这个工具的用法注释就写着「真 PostgreSQL（CI / 生产同构）」
⇒ 它正是会被拿去连生产的那一个。
CI 里用 `trust` 认证（连接串不带口令）所以 CI 日志是干净的，
**人工对生产跑一次就漏一次**。

## 修法：给出口径只写一遍

新增 `app/common/database.py::describe_database_url()`——**唯一的**打印口径：

| 输入 | 输出 |
| --- | --- |
| 生产连接串（带「用户名:口令@主机」前缀） | `postgresql+psycopg://<主机>:5432/<库名>（口令已隐藏）` |
| 本地 SQLite 路径 | `sqlite:///./dev.db` |
| 没设 | `<未设，走默认>` |
| 解析不了 | `<无法解析的连接串（已隐藏）：ValueError>` |

三条取舍：

1. **口令不输出**——红线。
2. **用户名也不输出**——它不是机密，但没有展示价值；最小暴露面永远是对的。
3. **解析失败不回显原文**——回显＝把口令又漏一次。宁可显示「无法解析」。

⚠️ 只捕获**解析类**错误（`ArgumentError` / `ValueError`），其余异常（代码写错）必须炸出来。
这是本次实测踩到的：`SQLAlchemy` 的 `URL` 上**没有** `dialect` 属性（只有 `get_backend_name()`），
最初的宽 `except` 把这个 `AttributeError` 一起吞了 ⇒ **所有**输入都显示「无法解析」，
是测试（sqlite 用例）把它抓出来的。脱敏函数**默默降级**比崩掉更危险。

## 门禁补强：新规则 `raw-db-url-echo`

判据：**同一行**里同时出现

1. **输出口**（`print` / `logger.info` / `logging.warning` …）
2. **连接串来源**（`DATABASE_URL` 环境变量 / `settings.database_url`）

⇒ 就是「把连接串直接打进输出」的那一行。

**正确写法**必须先过脱敏函数，且**分两行**写（先取值、再打印脱敏结果）——
规则只认「来源与输出口同行」，所以这个写法不会被误伤（不误伤很重要：
否则大家会绕过门禁）。

规则对**全仓库**生效，**不给测试开豁免** ⇒ 连测试文件里写反例都得运行时拼接。

## 验证

新增 15 条用例（`backend/tests/test_database_url_masking.py` 9 条 +
`backend/tests/test_scan_secrets_raw_db_url_rule.py` 6 条）：

| 断言 | 抓什么 |
| --- | --- |
| 口令不出现在脱敏结果里 | 红线 |
| 用户名也不出现 | 最小暴露面 |
| 主机与库名**保留** | 脱敏不能把运维要的信息也丢了 |
| 没有口令时**不许**谎称「口令已隐藏」 | 不说假话 |
| SQLite 路径原样显示 | 另一条分支的形状 |
| 解析失败**不回显原文** | 失败路径也是泄漏路径 |
| **工具真的打印的那行**里没有口令 | 钉住这次修复本身 |
| 新规则命中「同行回显」 | 门禁补强生效 |
| 新规则**不**命中正确写法 / 普通打印 | 不误伤 |
| **仓库自己**过新规则 | 新规则不得把已有代码判红 |

**变异测试**：把工具的脱敏临时撤掉（改回打印原值）⇒
`test_tool_prints_masked_target_not_the_raw_url` **变红** ⇒ 断言不是恒真的空转断言。

## 遗留（本笔**不**解决）

  （口令进了会话输出）仍需人工轮换（阿里云 RDS 控制台改密码 + 更新服务器环境变量）。
- 本笔**没有**改任何连接串、也没有碰生产数据库。
