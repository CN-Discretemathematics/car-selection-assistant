# 「我记住的偏好」：让用户看得见、能撤回（2026-10-21）

> 分支：`feat/memory-management-entry`

## 一句话

跨会话记忆（预算 / 用途 / 人数 / 排除项）会**改变下一次推荐的硬约束**，
而后端早就备好了「列出」与「撤回」两个接口，但前端**没有入口**——
用户既看不到自己被记住了什么，也没法撤回。现在补上这个入口。

## 为什么这不是「nice to have」

1. **体验**：记忆会改硬约束。用户看不到 ⇒ 不知道推荐为什么突然变了。
2. **隐私**：说「你被记住了什么、怎么撤回」才叫透明；只有一个
   「清除浏览器数据」是**粒度太粗**的补救。

## 入口在哪

智能导购面板底部一行「**我记住的偏好 ›**」→ 打开面板 → 逐条「不再记这条」。

放这里而不是单独开一个页面，理由：记忆**产生于对话**，那么它的管理入口
也该**在对话旁边**——用户问完车，顺手就能看见「我刚才说的那些被记住了」。

## 三条诚实性约束（实现里都钉住了）

| 约束 | 为什么 | 实现 |
| --- | --- | --- |
| **读不到 ≠ 没有** | 空列表会被读成「你什么也没被记住」——那是谎 | `listPreferences` 失败**抛错**；面板显示「读取失败」而不是空列表 |
| **不凭空创建身份** | 只想看一眼的人，不该凭空多出一个身份 | 列表用 `readIdentityToken()`（只读），**不**调 `ensureIdentityToken()` |
| **撤回即时可见** | 撤回后列表里还留着那条 = 用户以为没生效 | 撤回成功后立刻从列表移除，不等下次刷新 |

## 值的渲染：说人话

后端存的是字符串（列表是 JSON 数组、人数是十进制、预算是 `{"min":…,"max":…}` 单位元），
界面不能直接把 `{"min": 150000, "max": 250000}` 甩给用户。

⇒ `web/lib/preferences.ts::describePreference` 负责说人话，
**只写一遍**（列表项与提示共用）。规则：

| 键 | 显示 |
| --- | --- |
| budget | 预算：15 万元 ~ 25 万元 / 不超过 25 万元 / 15 万元 起 |
| passengers | 用车人数：5 人 |
| usage | 用途：家用、通勤 |
| body_type | 车型类别：SUV、轿车 |
| energy_preference | 能源偏好：纯电 |
| avoid | 不想要：纯电、MPV |
| brand_exclude | 不想要的品牌：丰田 |

解析不出来就**原样显示**——不补 0、不猜单位（与全站「缺失要显式」的口径一致）。

## 与「观察阶段」的关系（重要）

生产闸门当前是 `shadow`（只记录、不生效）⇒ **此刻这个清单永远是空的**。

这是**如实**的（确实还没记住任何东西），但也别让文案说谎：
面板的空状态写的是「现在还没有记住任何偏好」——**不含**「观察阶段」字样
⇒ 切到 `on` 之后，这句话依然成立，不需要改文案。

「目前处于观察阶段」那句话仍然只写在**隐私页**（那里才是它的位置），
切 `on` 时删那一句即可（页内已留注释）。

## 边界

- 本笔**不改**后端接口，也不改记忆的写入策略（闸门仍由 `DURABLE_PREFS_MODE` 说了算）。
- 撤回后**下一次**会话起不再生效；当前这段对话里已经说过的话不受影响
  （那是会话内状态，用户可以在会话里「新对话」重置）——这一点写在面板提示里。
