## 1. 解释路径数字守卫（**已完成**）

**目标**：解释路径（`_explain`）产出的每句数字都能追到候选款型 / 检索证据 / 画像，
把「每句数字可溯源」从口号变成机制。

✅ **实施结果**：见 [解释路径的数字守卫](2026-10-21-explain-path-number-guard.md)。
判据照 ADR-0005：只守数字、允许集复用 `tool_result_universe`（与工具循环**同一套**）、
三级处理（重写一次 → 回退模板 + `contract_fallback` 打标）。
⇒ 待立项项里**第 1 项已闭合**（第 4 项同日闭合）。

### 现状（行号为 origin/main `5f535ab`）

| 事实 | 位置 |
| --- | --- |
| 解释路径**无任何数字守卫**，只过 `safety_guard` | `backend/app/agent/engine.py:2587` `_explain` |
| 工具循环的三级处理（违规 → 重写一次 → 回退模板 + `contract_fallback`） | `engine.py:2113-2152` |
| 对比路径的数字白名单 | `engine.py:1688` |
| 判定函数（数值 + 0.01 容差） | `backend/app/agent/answer_contract.py:98` `answer_numbers_allowed` |
| 数字提取 | `answer_contract.py:57` `numbers_in` |
| 工具返回的数值 / 名字池 | `answer_contract.py:176` `tool_result_universe` |

### 判据（A/B 实测）

开关沿用三模式闸门：`AGENT_EXPLAIN_CONTRACT_ENABLED`（`off → shadow → on`）。

| 指标 | on 的要求 | 怎么测 |
| --- | --- | --- |
| 池外数字条数 | **恒为 0** | 解释回答逐条过 `answer_numbers_allowed`，池外即计一次 |
| 回退模板后的池外数字 | **恒为 0** | 模板是确定性的，若不为 0 说明允许集漏了模板用的数 |
| `contract_fallback` 触发率 | **先测分布再定阈值**，不预先拍 | shadow 阶段采样分布 → 再定线 |

⚠️ **空转断言防护**：守卫必须先断言**允许集非空**——若允许集为空，`answer_numbers_allowed`
会把任何非空回答都判成违规（恒真），或被短路成恒过。解释路径在候选为空时走模板早退分支，
不进守卫；这一点要有用例钉住。

### 改动面

- **改**：`engine.py::_explain`（就地接守卫，不新建第二个守卫 module）。
- **可能改**：`answer_contract.py` 加一个「量纲补齐」的小函数（把万元量纲补进允许集）。
- **不改**：候选集、8 维打分、排序、路由（红线）。

### ⚠️ 必须先解决的量纲坑

`answer_numbers_allowed` 比的是**数值 + 0.01 容差**，而画像里的预算存**元**（`200000`），
文案写「**20 万**」→ 文本解析出 `20` → 与池里的 `200000` 差 4 个数量级 ⇒ **被误判成编造**。

工具循环没踩到，是因为它的允许集**含用户原话里的数字**（`engine.py:2018` `numbers_in(message)`）；
解释路径的用户消息不一定带数字 ⇒ **允许集必须同时补万元量纲**（`budget.max / 10000` 等）。
**这是实施的第一步，不是可选项。**

### 测试

复用 `backend/tests/test_answer_contract.py` 已有的 `_FakeLLM` 范式（守卫本身**不需要** LLM key），
四条路径各有断言：合法通过 / 数字违规→重写 / 重写仍违规→回退模板 / LLM 不可用→回退模板。
另加一条量纲用例：预算 `200000` → 文案「20 万」**必须通过**。

### 验收

`backend\.venv\Scripts\python.exe -m pytest -q`（backend/ 下）·
`python -m ruff check .`（基线不上升）· 单轮评测 520/520 + 硬约束违规 0 ·
`python reviewer/scan_secrets.py` / `python reviewer/scan_ui_copy.py` 退出码 0。

## 2. 款型级反馈影子评估

**目标**：给「一次拒绝该记到什么粒度」提供**证据**——款型级拒绝如果上升为**车系级排除**，
会误伤多少台。

### 现状

| 事实 | 位置 |
| --- | --- |
| 反馈表按**款型级**记（车系级拒绝写入时展开成全部在售款型） | `backend/app/common/models.py:442` `VariantFeedback` |
| 现有影子是**品牌级**排除的反事实 | `engine.py:1006` `_shadow_rejection` + `backend/app/agent/rejection_shadow.py:34` `brand_exclusion_delta` |
| 品牌级实测误伤面均值 **1.27**、中位 1、最大 3 | [拒绝反馈的影子评估](2026-10-21-rejection-shadow-evaluation.md) |

### 拍板结论

- 触发：**仅款型级**反馈触发（车系级拒绝已在写入时展开成款型级，天然覆盖）。
- 反事实：加**车系级排除**（不是品牌级）后重跑推荐，算差集。
- 落点：**一行 JSON 日志**，**不建表**、**不进反馈表**（用户反馈 ≠ 内部评估，两回事）。
- 记录：**差集明细全记**（entered / left 的**台数与 id 列表**，不只记计数）。
- 聚合：**先不做在线聚合**——离线脚本聚合（一次导出日志 → 统计分布）。

### 判据

聚合口径（离线）：按**车系**分组的误伤面分布 + 每个被拒车系对应的「同车系其它在榜台数」的
中位数 / 最大值 / P90。

拍板线（**先看分布再定，不预先拍**）：车系级排除的误伤面与品牌级实测同量级（中位 ≤1、最大 ≤3）
⇒ 车系级是一个可行粒度；显著更大 ⇒ 停在款型级。

⚠️ **空转断言防护**：影子必须**真的改变反事实画像**（把被拒车系加进排除）再重跑推荐。
若排除没生效，「同车系在榜台数」恒为 0 ⇒ 断言恒真。必须另有一条用例钉住
「反事实确实生效」（排除后该车系的其它款型确实不在榜）。

### 改动面

- **改**：`rejection_shadow.py`——把 `brand_exclusion_delta` **泛化**为按「组」算差集
  （`brand_exclusion_delta` 降为薄封装，既有调用点与既有 4 条用例**不动**）。
  ⚠️ **不新建第二个影子 module**：同一件事写两遍必然漂移。
- **改**：`engine.py::_shadow_rejection`——多算一次车系级反事实。
- **不改**：推荐结果（影子只算不改）、反馈表的写入路径。

### 测试与变异

现有 4 条用例 + 3 条新增变异必须**红**：反事实没生效 / 差集算成交集 / 影子写进了反馈表。

### 验收

pytest 全绿 · ruff 基线不上升 · 影子开着时**用户看到的回答逐字不变**（现有用例已钉住）。

## 3. 账户合并可观测面

**目标**：用户能自查「我的数据被搬过多少」——每次合并留一行记录，设置页展示。

### 现状

| 事实 | 位置 |
| --- | --- |
| 合并接口返回搬了几条，但**不留记录** | `backend/app/auth/router.py:189` `POST /auth/merge-identity` |
| 模型层**没有合并记录表** | `backend/app/common/models.py`（无 `IdentityMergeRecord`） |
| 设置页候选落点：登录态页面底部（`web/app/favorites/page.tsx` 已有注销账号入口）；`web/app/privacy/page.tsx` 是**静态政策页**，不适合放动态记录 | — |

### 改动面

- **改**：`models.py` 加 `IdentityMergeRecord`（时间、匿名身份 id、账户身份 id、记忆条数、反馈条数）
  + 一条迁移（**接在 `c3d4e5f6a7b8` 之后，单头不分叉**）。
- **改**：`identity_merge.py::merge_anonymous_into_user` 写一行记录。
- **改**：`web` 登录态页面展示「已从匿名设备合并 N 条记忆」。
- **改**：客户端在合并成功后**换用返回的新账户身份 token**（[ADR-0006](adr/0006-anonymous-identity-invalidated-on-merge.md) 的硬约束）。

### 判据

| 判据 | 说明 |
| --- | --- |
| 合并后 `GET /me/data` 仍看得到搬过去的数据（**没有** `/auth` 段 ⇒ 照实现来） | 搬家没坏 |
| 旧匿名 token 立即 404 | 失效语义没退 |
| 重复合并**不再新增记录行** | 幂等 |
| 页面显示的 N 与记录表一致 | 展示不是幻觉 |

⚠️ **空转断言防护**：「N 与记录表一致」若前端读的是**同一次合并响应里的内存值**，则恒真。
前端必须**重新拉取**记录列表再渲染。

### 风险

- 客户端不改（不换 token）⇒ 用户合并完立刻失忆。**这是本项唯一的必改项**，
  必须与后端同一次上线。
- 合并记录里含匿名身份 id——属于内部标识，展示层不要裸露。

### 验收

pytest（新增用例）· alembic **单头** · `pnpm --dir web exec tsc --noEmit` ·
`cd web` 后 `pnpm exec eslint . --max-warnings 0` · `next build`（先停 `next dev`）·
文案门禁 `scan_ui_copy.py`（新增展示文案要过审）。

## 4. 离线重放评估

**目标**：给「**硬约束排除项是记忆的第一价值**」一个**近似**证据。
这是计划 §七 唯一一条「产品直觉、未做用户测试」的核心判断。

⚠️ **真实用户测试仍是最终判据**——自动化做不了。本项只是把「直觉」推进到「有本地证据」。

### 现状

| 事实 | 位置 |
| --- | --- |
| 每轮对话留档（用户输入、回复、路由决策、解析出的车系、画像快照） | `backend/app/common/models.py:525` `AgentTurnLog` |
| 写入前做 PII 掩码；取回需**管理员级凭据**（与 `/admin` 同一套）；保留期默认 **30 天**（`AGENT_CONVERSATION_LOG_RETENTION_DAYS`） | `backend/app/common/config.py:43` |
| 清理入口 | `backend/app/agent/conversation_log.py:155` `purge_expired` |

### 数据来源（**2026-10-21 复盘后修正**）

原拍板是「生产库导出为主、本地合成为辅」。**复盘后这个前提不成立**：
生产库**没有真实对话**可导（`agent_turn_logs` 长期 0 行；近 14 天 nginx 43,660 条请求里
agent 端点只有 `GET /sessions`，**消息 POST 次数为 0**）⇒ 导出也是空的。

**修正为：本地合成为主**（用现成 200 题多轮题库），产出见
[记忆的边际价值](2026-10-21-memory-value-offline-replay.md)。

⇒ 因此本项**不再等生产数据**；它真正的阻塞是「没有真实用户行为」，
而那个只能靠**真实用户测试**（生产至今零对话流量，暂时无从谈起）。

### 重放设计（合成会话版，已实施）

1. 取跨会话记忆场景（预算回访 / 预算删除 / 拒绝跨会话），各 50 题；
2. **同批场景跑两遍**：`DURABLE_PREFS_MODE=on` vs `off`（同一进程内切换，
   `get_mode()` 每次调用现读环境变量）；
3. 每个场景新建匿名身份 ⇒ on 组写下的记忆**不会**漏进 off 组；
4. 比较每类的通过率（= 1 − 违规率）与差值 Δ。

| 指标 | 方向 |
| --- | --- |
| 记忆生效组的通过率 | 应**显著高于**不生效组 |
| off 组仍全过的类型 | 判「**不构成对照**」（断言恒真），不计入「有效」 |

⚠️ **空转断言防护**：`off` 组也 100% 通过 ⇒ 该类场景**验不到任何东西**
（这正是「删记忆」场景曾经的毛病：记忆功能整体关闭时照样 50/50 通过）。
工具把这种情况单独标成「不构成对照」，与「记忆没起作用」**分开**。

### 改动面

- **已新增**：[记忆边际价值评估工具](../backend/tools/eval_memory_value.py) + 它的用例
  + [记忆的边际价值](2026-10-21-memory-value-offline-replay.md)。
- **题库补了一类**：「**排除项跨会话**」场景（用户说「不要 X 品牌」→ 换会话 → 该品牌不再出现）
  + 新断言类型 `brand_not_recommended`（查结构化推荐结果里的品牌，不查正文裸字符串）。
  ⇒ §七 那条判断从「**不可测**」变成「**可测**」。
- **不改**：生产路径任何一行（除两处被测出的真缺陷修复：歧义品牌的排除项静默失效）。

### ⚠️ 当前阻塞

**没有**技术阻塞。剩下的是**证据强度**问题：合成会话只能给机制层证据，
「排除项是第一价值」这条**排序**判断要靠真实用户测试——
而生产至今零真实对话流量（前端已接线，见汇总表的复盘修正）。

## 5. D1.3 可抓取性调研

**目标**：D1.3「官方文档正文落库」**保持降级**——先回答「能不能判」，再回答「值不值得抓」。

### 拍板结论

- 门槛压在**判据可判定**，不是抓取成功率。
- 产出是**一页调研结论**，**不是**抓取器、**不是**表结构。

### 调研要回答的问题

1. 「官方文档正文」在本项目语境里指哪一类页面？（车系配置页正文？参数说明正文？两者都不是？）
2. 「这条正文可被抓取」的**可判定判据**是什么？判据必须满足：
   - 能写成**离线可跑的分类 / 统计口径**（不依赖人工逐条判断）；
   - 对在库车系能给出**适用率**（多少车系落在判据内）；
   - 判据不成立时能**确定地说不成立**（而不是「不确定」）。
3. 抓取成本的粗估（页面数 / 频次 / 对上游的压力）。

### 结论口径

- 判据**写不出来** → D1.3 **不立项**，本轮结案；
- 判据**能写出来**且适用率足够高 → 写一份**立项建议**（含抓取范围、落库形态、增量成本），
  但**仍然不写代码**。

### 改动面

**无代码改动**。产出是 `docs/` 下的一页调研结论。

## 全局纪律（每一项都适用）

1. **每个策略决策都要 A/B 实测**——不接受未经测量的效果断言。
2. **空转断言必须被变异测试抓出来**：恒真 / 概率性 / 自引用的断言一律不算通过。
3. **行为变更必须显式记录**（本仓已有行为变更表惯例）。
4. **同一件事写多遍必然漂移**——影子泛化而不是复制、守卫复用而不是另写一套。
5. **候选集不变式**是红线：以上五项**没有一项**允许改动硬约束筛出的候选集。
6. 一项一个分支；分支从最新 `origin/main` 拉；`main` 只走 PR。
