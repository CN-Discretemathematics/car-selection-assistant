### 切流观测链路（#55 → #56 两笔做完）

```
soft_prefs.py         记 illegal / status   →  shadow 日志（logger: app.agent.soft_prefs.shadow）
      ↓
soft_prefs_report.py  聚合 + 判定 + 退出码   →  markdown 报告
```

用法：`python -m app.agent.soft_prefs_report --file soft-prefs.log --out ../eval/sp.md`

判定分三档：**不通过**（越界率非 0 / `mode_applied` 非 0，退出码 **1**）、
**不可判定**（样本不足 / 字段缺失或形状不对 / `unknown` 非零，退出码 **2**）、
**通过**（0）。初版把「判不了」和「不通过」都返回 0，CI 会把「没测到」读成「通过」，已分开。

## 七、这一轮我和审查互相抓到的假绿灯（累计 7 次）

本会话我在**测试上**栽了 7 次，每一次都是**反向验证或 subagent 审查**拆穿的，
**没有一次是我自己发现的**：

1. 源码断言被 **docstring 里的字面量**骗过（`inspect.getsource` 含 docstring）→ 改 AST
2. `importlib.reload` **污染了别的测试文件**（`load_dotenv` 固化环境变量）→ 改子进程
3. 「LLM 不可用」那条用例是**空断言**（`except Exception` 吞掉假客户端的 `AssertionError`）
4. `status` 的兜底把「超时路径忘埋点」掩盖成 `no_response` → 改显式 `unknown`
5. 两条 `no_response` 出口**零测试覆盖**（删掉埋点 69 例全绿）
6. 假实现**自己新建 list**，从没往调用方的 out-param 写 → 测的其实是另一条路径
7. **加字段时忘了递增 `SOFT_PREF_VERSION`** → 旧记录会以干净身份混进分母

聚合器另有 **6 条**假绿路径，全部由审查构造输入实测发现（见第二节表格）。

**教训（值得写进 skills）**：本仓的假绿灯几乎都不是「算错」，而是
**「什么都没测到却报通过」**。每写一个统计/判定/守卫，都要用
「反向验证」确认它**真的**会在失效时变红——而且要专门去构造那些
「输入退化」的形态（字段缺失、形状不对、样本灌水、重复记录、非目标记录）。
