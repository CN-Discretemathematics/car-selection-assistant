# 解释路径的数字守卫（2026-10-21）

> 分支：`chore/merge-all-fixes`（收口分支）｜决定：[ADR-0005](adr/0005-explain-path-numbers-only.md)

## 一句话

解释路径（`engine.py::_explain`）此前**没有任何数字校验** ⇒ 模型编的数字
（如「续航 802 公里」）直接进用户屏幕。现在照抄工具循环的三级处理堵上了。

## 怎么发现的

不是读代码读出来的，是**先写失败场景**测出来的
（`backend/tests/test_agent_failure_scenarios.py` 的 S1）：

```python
fake = _FakeLLM([
    {"content": "汉L 续航 802 公里，电池 82.6 度，综合续航优秀。"},   # 编造
    {"content": "汉L 官方指导价 15 万元。"},                        # 重写后合规
])
answer = _ask(client, "预算15万，家里5口人，想要家用轿车")
assert "802" not in answer["explanation"]
```

修之前红的原文：
「解释里出现了库外数字 802（编造）⇒ 直接进用户屏幕。实际解释：汉L 续航 802 公里……」

## 判据（照 ADR-0005）

| 项 | 取值 |
| --- | --- |
| 允许集 | 候选款型（result）+ 检索证据（evidence）+ 画像（profile）里的数字 |
| 收数方式 | **复用** `tool_result_universe`（与工具循环**同一套**）⇒ 它已把「元 ↔ 万元」两种口径都收进来（`n / 10000`） |
| 守什么 | **只守数字，不守名字**（名字容差匹配误杀面更大） |
| 违规后 | 回灌违规项让模型**重写一次** → 再校验 → 仍不合格 → **回退确定性模板**并打 `contract_fallback` |

⚠️ **量纲**：画像里存的是元（150000），回答里常写「15 万」。
若允许集只收元，「15」会被判成编造 ⇒ 合法回答被误杀。
`tool_result_universe` 已经处理（`round(n / 10000, 3)`）⇒ 直接复用它，不另写一份。

## 为什么要「就地接在 `_explain` 内」

守卫逻辑**只有一份**（`answer_contract.py`），`_explain` 只是调用它并实现三级处理
——与工具循环（`engine.py::_tool_loop_reply`）**同构**。
不新建「解释路径专属的守卫 module」：同一个承诺写两遍必然漂移。

## 行为变更

| 场景 | 之前 | 之后 |
| --- | --- | --- |
| 解释里出现库外数字 | 直接给用户 | 回灌重写一次；仍不合规则回退确定性模板，并打 `contract_fallback` |
| 解释里只有有依据的数字（含「15 万」口径） | 给用户 | **逐字不变** |

⇒ 降级必须**可观测**：`_explain` 现在返回 `(文本, 是否回退)`，
调用方据此在 `filters` 上打 `contract_fallback`（与工具循环路径同名同义 ✓）。

## 验证

`backend/tests/test_agent_failure_scenarios.py`（5 个失败场景，**先红后绿**）：

| 场景 | 结果 |
| --- | --- |
| S1 解释路径编数字 | **红 → 修 → 绿** |
| S2 身份串台（A 的记忆影响 B） | 本来就绿 ✓ |
| S3 撤回记忆后仍生效 | 本来就绿 ✓ |
| S4 同轮排除不生效 | 本来就绿 ✓ |
| S5 空候选编车 | 红 ⇒ 查出是**断言过早**（引擎先追问是合理行为）⇒ 改断言后绿 |

S5 那次「红」值得记一笔：它不是产品缺陷，是**我写错了判据**
（第一版在引擎还在追问时就断言「必须说没有合适的车」；
而且每轮都新开会话 ⇒ 画像不累积 ⇒ 引擎永远从头追问）。
⇒ 判据要**等条件问齐之后**再下，且追问必须发生在**同一会话**里。
