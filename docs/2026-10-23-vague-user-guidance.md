# 说不清需求的用户：不再被反复问，也不再一款车都拿不到（2026-10-23）

> 来源：生产**真实用户会话**（`agent_turn_logs`，2026-10-23 12:47，session `e4f8bf12…`）。
> 分支：`fix/agent-vague-user-guidance`

## 一句话

用户回「都可以」（= 对追问的回答）此前被判成**闲聊** ⇒ 绕开推荐链 ⇒
一款车都拿不到；而且那句「用途不限」**只活在 LLM 的措辞里、没回写画像**
⇒ 下一轮确定性追问仍把用途当缺失 ⇒ **同一个问题连问三遍**。

## 生产实测：那段对话逐轮

| 轮 | 用户说 | 助手回答 | 问题 |
| --- | --- | --- | --- |
| 0 | 「15万预算有什么能选的」 | 追问卡（正文空） | 用户**明确要清单**，却一款车都没拿到 |
| 1 | 「都可以」（答用途） | 「还差一项：平时主要坐几个人」 | 这句本身还行（问的是另一项） |
| 2 | 「2人」 | 「已记住…**还差一项：主要用途是什么？**」 | ❗**又问用途**——用户已答「都可以」 |
| 3 | 「都可以」（第二次） | 「**没法凭预算直接列一份推荐清单**」 | ❗库里明明有 870+ 款在售、预算内能列 5 款 |
| 4 | 「suv」 | 「已记住…**还差一项：主要用途是什么？**」 | ❗**第三次问用途** |

路由决策（同一会话的 `agent_turn_logs`）：

| 轮 | intent | matched_rule |
| --- | --- | --- |
| 1、3 | **`chitchat`** | `1:not(has_car_intent or structured)` |
| 0、2、4 | `recommendation` | `4:recommendation_fallback` |

⇒ **「都可以」被当成独立话题**（既无购车关键词、也无结构化线索），
自然落进闲聊分支——而它其实是**对上一轮追问的回答**。

## 三个根因（都定位到具体代码）

1. **路由层**：纯回答没有购车意图 ⇒ `chitchat` ⇒ 绕开推荐链；
   LLM 自由发挥且**不回写画像** ⇒ 下一轮追问又问一遍。
2. **画像层**：没有「用户已放弃某一项」这个状态 ⇒ 放弃只存在于回复措辞。
3. **追问层**：用户明确要清单时仍发追问卡 ⇒ 答非所问。

## 改了什么

### 1. 路由规则 1b：「对追问的回答」走推荐链

`app/agent/routing.py`：`gives_up_on_profile()` 与 `_GIVE_UP_RE` **下沉到 routing**
（此前在 engine.py，但判据要结合 `profile.unknowns`——**只有路由层拿得到画像**；
两处口径不一致正是本缺陷的根因）。

```python
if gives_up_on_profile(message) and profile.unknowns:
    return RouteDecision(intent="recommendation", matched_rule="1b:give_up_answers_pending_clarification", ...)
```

守卫：**没有在追问时**（「都可以」作为首句）仍走闲聊——不回归。

### 2. 画像层：`waived_dims`——用户放弃过的维度不再问

`app/agent/schemas.py` 新增 `UserProfile.waived_dims`（与 `probed_dims` 同构：
都是「别再问」，但含义不同——`probed_dims`=「问过了（软偏好维度）」，
`waived_dims`=「用户说不限（硬约束维度）」）。

`engine.respond` 命中放弃表达时 `_waive_dim(profile, missing)` 记下**被放弃的那一项**；
`next_clarification` 跳过这些维度 ⇒ **同一个问题不许问第二遍**。

**为什么记在 engine 而不是 turn.py（画像推进的归属）**：
`waived_dims` 是**事件驱动**字段（和 `rejected_variant_ids` / `shown_series_ids` 同类）——
「用户本轮放弃了这一项」是本轮的事件。更关键：**只有 engine 知道放弃的是哪一项**，
那一项正是它此刻在追问的（`missing`）；若提前在 turn.py 记下，
`next_clarification` 会**换一题**、判定随之偏（「随便推荐吧」会变成追问人数，
而不是既有语义要求的温和引导）。
⇒ 契约测试 `test_profile_advance.py::test_engine_no_longer_assigns_profile_fields`
的白名单里已登记该字段（附理由）。

**⚠️ 语义边界（2026-09 用户拍板，勿改）**：
「随便」= **跳过当前这题、继续问下一项**，不是「什么都别问、直接给车」。
既有测试 `test_agent_clarify_twice_then_guides_gently` 钉着这一点：
「预算15万，随便推荐吧」⇒ 继续追问用途；「想要纯电的车」+「随便推荐吧」
（**没有核心画像**）⇒ 温和引导、**不硬推**空画像推荐。
本次改动**没有动**这两条语义，只是让「被放弃的那一项」不再被问第二遍。

### 3. 追问层：用户要清单时**不阻塞**

`app/agent/routing.py` 新增 `asks_for_candidates()`（「有什么能选的」「有哪些能选」
「帮我选几款」「选哪些车」…）。

`engine.respond` 首次追问分支：命中该问法**且画像已有预算** ⇒ 不发追问卡，
直接进推荐链；缺口改用 **`followup` 尾巴**（`next_clarification` 的结构化缺口）。

守卫：**没有预算仍然先问预算**——预算是硬门槛，没有它就没有「预算内」这个范围。

### 4. followup 优先级：硬缺口优先于软偏好

推荐链里 `followup` 先取**硬缺口**（用途/人数），没有才取软偏好追问
（空间/动力）。硬缺口更影响筛选。（正常路径下画像已全 ⇒ 行为不变。）

## 边界

- 只改**说不清需求**这一条链路的判定，不动推荐打分、不动硬约束语义、不动数据；
- 「用户放弃**哪一项**」由「当前正在追问什么」决定 ⇒ 答完一项仍可问另一项
  （真人销售：用途随便，那几个人坐？——这是**引导**，不是重复）；
- 用户要清单但**没有预算** ⇒ 仍先问预算（预算是硬门槛）。

## 顺带修掉的一个隐患：模型可能替用户编

画像不全也进推荐链 ⇒ 模型会看到 `usage: []` ⇒ **可能替用户编一个用途**
（「适合家庭出行」）——用户从没说过的偏好被当成他说过的。

⇒ `_explain_system_prompt` 在**画像有缺项时**补一句：
「用户还没说的：用途、乘坐人数——**不要替他假设**」；
被用户放弃的维度则说「用户明确表示不限的：用途——**不要替他猜一个具体的**」。
**画像完整时提示一个字都不改**（绝大多数轮次，既有行为逐位不变）。
