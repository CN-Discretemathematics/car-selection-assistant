# 「一家四口」也算人数：家庭规模的口语说法没被解析（2026-10-22）

> 来源：2026-10-22 生产实测（12 条代表性探针）+ 本地解析基线核对。
> 分支：`fix/household-size-phrase`

## 一句话

人数解析要求带「人」字 ⇒ **「一家四口」「四口之家」「一家五口」一律读不出人数**
⇒ 用户明明说了家里几口，Agent 还会追问「几口人？」，首轮直接推 0 款。

## 缺陷（生产实测，不是推演）

2026-10-22 在生产跑 12 条代表性探针，其中「**预算35万，一家四口，长途出行SUV**」
这一轮 **0 款推荐**。查下来不是库里没车，是 Agent 认为用户**没说人数**，
转去走「最小化追问」分支（`need_clarification=True`）。

本地解析基线（修复前）：

| 文本 | 结果 |
| --- | --- |
| 「一家四口」 | `None` ✗ |
| 「四口之家」 | `None` ✗ |
| 「一家五口」 | `None` ✗ |
| 「我们一家5口」 | `None` ✗ |
| 「四口人」 | 4 ✓ |
| 「一家四口人」 | 4 ✓ |
| 「5人以上」 | 6 ✓（开区间 +1） |
| 「6座」 | 6 ✓ |
| 「一家四口，要6座的车」 | 6 ✓ |
| 「三两口菜」 | `None` ✓（不误判） |

## 根因

`app/catalog/series_constraints.py::_PASSENGERS_PEOPLE_RE` 要求「人」字收尾：

```
([一二两三四五六七八九十\d]+)\s*(?:个|口)?\s*人\s*(以上|开以上|或以上|以内|以下|之内|内)?
```

「四口人」能命中（口+人），「一家四口」不能（缺「人」）⇒ 返回 `None`。

## 修法

新增一条**家庭语境**的人数写法，只认两种带语境的形式：

```
一家N口   |   N口之家
```

放在 `parse_passengers` 的**兜底**位置：**人数分支与座位分支都没命中时**才生效。

### 三条口径保证

1. **现有表达逐位不变**——「四口人」「5 人以上」「6 座」走的还是原分支；
   开区间的 +1（人数侧）与含端点（座位侧）一个字都没动。
2. **明确的座位硬约束优先**——「一家四口，要6座的车」仍取 **6 座**，
   不会被兜底抢成 4（否则会把用户的车砍到 4 座）。
3. **兜底值是确切人数**，**不套开区间 +1**——「一家四口」= 4 口；
   +1 是「超过 N 人」的产品口径（「5 人以上」= 6 座），与家庭规模无关。

### 为什么不裸匹配「N口」

「三两口菜」「两口锅」会被读成 3 口 / 2 口。当前实现对这两句返回 `None`
（测试里有反例断言），所以兜底**必须带家庭语境**（`一家` 前缀或 `之家` 后缀）。

## 验证

新增 `backend/tests/test_vehicles_passengers_household.py`（12 条）：

| 断言 | 抓什么 |
| --- | --- |
| 家庭前缀 / 后缀 / 句中都能解析出确切人数 | 缺陷本体 |
| **「一家四口」==「四口人」==「四口之家」** | 同一语义两种写法必须一致（同一件事写多遍必然漂移） |
| 人数分支逐位不变（5 人以上=6、5 人以内=5） | 别顺手改产品拍板的开区间口径 |
| 座位分支逐位不变（5 座以上=5） | 座位侧含端点 |
| **「一家四口，要6座的车」= 6 座** | 兜底不得抢走明确的座位硬约束 |
| 「三两口菜」「两口锅」「四口」= `None` | 兜底不得误判 |

**变异测试**：把兜底掐掉（`household = None`）⇒ **4 条变红**
（家庭前缀 / 后缀 / 句中 / 等价性），其余 15 条仍绿 ⇒ 断言抓的是真缺陷，不是空转。

**回归**：既有 `backend/tests/test_seat_disclosure.py`（7 条）全绿。

## 影响面

`parse_passengers` 是**人数解析的唯一实现**（2026-10-05 已收敛），
两个消费点都走它：

- `app/agent/turn.py::extract_hints` ⇒ Agent 画像的 `passengers`；
- `app/catalog/series_constraints.py::parse_budget_and_seats` ⇒ 约束下推。

⇒ 修一处，两条路径同时生效，且**不存在第二个实现**（这是 2026-10-05 那次事故的教训：
两个调用点各自 `.search()` + 取组号，于是「5 人以上」被当成 5 座）。

## 边界

- 这是**解析覆盖缺口**，不是产品口径变更：用户说「四口人」与说「一家四口」
  本来就是同一件事，修之前它们结果不同。
- 兜底只影响**当前解析不出人数**的输入 ⇒ 已能被解析的输入**零影响**。
